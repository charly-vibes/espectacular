* Architecture facts (espectacular src)

- =check.rs --run-tests= iterates ALL resolved scenarios × ALL contract
  entries (shell/custom/property/snapshot). No selection today.
- Contract TOMLs are 1:1 derived from spec files → free language-agnostic
  selection edge: changed spec file → scenario → contract.
- =TestEntry { flags, command, timeout_seconds }= + =compose_command= already
  support filter injection per binding.

* Design conclusion (best way across languages)

Layered selection:
1. *Layer 1 (always, no testaruda)*: capability-level selection inside ah.
   Changed files (git) → affected spec files → scenarios → contracts. Skip
   untouched capabilities. Fixes the dominant cost for every language.
2. *Layer 2 (only if testaruda store exists)*: refine within selected
   scenarios via =testaruda select --files=; drop contract bindings whose
   underlying tests are provably unaffected; inject filters where the
   archetype supports them.
3. *Exit 20 semantics*: EMPTY means "no *code* affected" → do NOT benign
   pass-through to running nothing; still run Layer 1's spec-side selection.
   A spec change must always verify its own contracts (avoid false-green).

TDD shape: red = (a) changed spec file → only that capability's contracts run,
selection reported in JSON; (b) seeded testaruda store + changed code file →
further pruning, =--all-tests= escape hatch.
